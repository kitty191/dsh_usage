# 热力图颜色规格（已定稿）

> 状态：**已拍板**，作为 M6 的实现契约。
> 数据来源：`lib/stats.mjs` 的 `days[day].tokens`。

## 一句话

每天视图的颜色代表**当天的 token 用量**：浅色主题用量越多蓝色越深，深色主题用量越多蓝色越亮。每天视图用**固定阈值**，不随最近最高值漂移。

---

## 1. 每天视图：5 档 + 空白

| 档位 | 判定 | 含义 |
|---|---|---|
| 0 | `tokens === 0` | 空白格（当天没用） |
| 1 | `0 < tokens < 10,000,000` | 轻度 |
| 2 | `10,000,000 ≤ tokens < 30,000,000` | 中等 |
| 3 | `30,000,000 ≤ tokens < 60,000,000` | 较多 |
| 4 | `60,000,000 ≤ tokens < 120,000,000` | 高 |
| 5 | `tokens ≥ 120,000,000` | 顶格 |

- 阈值是"进入该档的起点"，所以**正好 1000 万**算第 2 档；1000 万以下才是第 1 档。
- 原方案里的 8000 万已**合并**进第 4 档（6000 万 ~ 1.2 亿），保持 5 档易分辨。
- **超过 1.2 亿不再加档**，仍显示第 5 档，悬停显示真实数字。

## 2. 每周视图：阈值 × 7

周总量天然是日总量的 7 倍左右，直接套日用阈值会让所有周都变成最深色。

| 档位 | 判定 |
|---|---|
| 1 | `< 70,000,000` |
| 2 | `70,000,000 ≤ x < 210,000,000` |
| 3 | `210,000,000 ≤ x < 420,000,000` |
| 4 | `420,000,000 ≤ x < 840,000,000` |
| 5 | `≥ 840,000,000` |

图例在每周视图下显示这组周阈值，不显示日阈值。

**呈现方式**：每周视图只画一行，每列一格代表一周；不会把同一周的颜色重复画在 7 个格子里。

## 3. 累计总量视图：相对渐变

累计值随账号使用时长增长，固定阈值没有意义。这一档是**唯一的相对缩放**：

```js
level = Math.min(5, Math.max(1, Math.ceil(5 * cumulative / total)))
```

- `total` 是 **12 个月窗口内的总量**。客户端从报告的 `days` 中截取当前窗口的数据，累计从窗口起点开始算。
- 比值 20% 以内为第 1 档，100% 为第 5 档。
- 效果：累计越多，浅色主题蓝色越深，深色主题蓝色越亮，表达"积累过程"。
- 图例在这一档显示"少 → 多"的相对刻度，**不显示具体数字**，避免误解为绝对用量。

## 4. 判定函数（M6 实现）

```js
const DAILY = [10_000_000, 30_000_000, 60_000_000, 120_000_000]

export function heatLevel(value, { view = 'daily', total = 0 } = {}) {
  if (!Number.isFinite(value) || value <= 0) return 0
  if (view === 'cumulative') {
    if (!Number.isFinite(total) || total <= 0) return 0
    return Math.min(5, Math.max(1, Math.ceil((5 * value) / total)))
  }
  const thresholds = view === 'weekly' ? DAILY.map((n) => n * 7) : DAILY
  let level = 1
  for (const threshold of thresholds) {
    if (value >= threshold) level++
  }
  return level
}
```

实际阈值集中定义在 `lib/client.js` 的 `DAILY_THRESHOLDS` / `WEEKLY_THRESHOLDS`，上面代码仅为算法示例。改阈值会改变历史用量对应的色阶，需要同步更新文档与测试。

## 5. 颜色定义

使用两套不透明蓝色色阶，色值集中在 `lib/client.js` 的 `HEAT_COLORS`。浅色主题用量越高蓝色越深，深色主题用量越高蓝色越亮。

| 档位 | 浅色主题 | 深色主题 |
|---|---|---|
| 1 | `#c9ddfc` | `#294261` |
| 2 | `#8bb7f2` | `#365f8f` |
| 3 | `#4a8be3` | `#4484c4` |
| 4 | `#2365c7` | `#62a8ea` |
| 5 | `#164398` | `#a0d2ff` |

旧版对同一个 `#4d93f8` 调整透明度，浅色主题即使用量很高也只能达到较浅的蓝色；独立色阶让高用量能达到深蓝，且不受面板底色影响。深色主题也不用宿主的 `brand-primary`，因为该变量在深色面板上对比不足。

- 实现方式：`HEAT_CSS` 由色阶数组生成 `[data-level]` 规则，深色覆盖走 `body[data-ds-dark-theme]`。图例与格子共用色阶，主题切换不需要重新请求统计。
- 空白格：`--dsw-alias-bg-layer-2` 打底 + 1px `--dsw-alias-border-l3` 内描边。
- 悬停格：1px `--dsw-alias-border-l3` 外描边，不改变底色。
- 提示框背景在明暗主题下都是深色，文字固定白色（`#ffffff`）。

## 6. 图例与交互

**图例（固定在热力图下方）**

```text
少  ▢ ▢ ▢ ▢ ▢  多
```

数字阈值不再显示在界面上——要查具体数字时，悬停格子即可。

**悬停**

```text
2026-10-18 · 48,073,103 tokens
```

- 每格是 `<div>`，带 `aria-label`；**不设置 Tab 焦点**——371 个格子会成为键盘陷阱。
- 悬停用自定义 tooltip，背景取自主题变量、文字固定白色，不引入第三方库。
- 颜色不是唯一信息渠道：悬停即可读到完整数字。

**网格**

- 列 = 周，行 = 周一…周日（中国习惯，周一起始）。
- 单元格高度 10px，宽度随列宽自适应；间距 2px，圆角 2px。
- 53 列按容器宽度平分（`repeat(N, minmax(0, 1fr))`），正常情况下 12 个月一屏可见；容器最小 520px，更窄时横向滚动并自动停在最右（最新）一端。
- 只渲染到"今天"为止；未来日期渲染为不可见格，不响应悬停。
- 月份刻度标在包含每月 1 日的列上方，即使 1 日不是周一也会标记。开头的残缺月份若与下个月相距不足三列，只省略开头旧标签，保留后续月份；最后一列刚进入新月份时也显示刻度。

## 7. 边界情况

| 情况 | 行为 |
|---|---|
| 完全没有数据 | 全部空白格，图例照常显示 |
| `total === 0` 且累计视图 | 全部空白，不除零 |
| 正好等于阈值 | 进入更高一档（`>=`） |
| 负数或非数字 | 按 0 处理 |
| 超过 1.2 亿 | 第 5 档，悬停显示真实值 |
| 周视图第一/最后一周不完整 | 按实际天数求和，不按比例外推 |

## 9. 变更须知

- 阈值改动会影响全部历史颜色，属于视觉破坏性变更，需要同步改本文档与测试。
- 不要改成"按当前最大值缩放"：那会让同一天的深浅随时间漂移，跨月比较失去意义。
- 累计视图的相对缩放是**唯一例外**，改它之前先确认用户是否真的需要绝对阈值。
