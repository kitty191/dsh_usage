# 开发笔记

> 每条格式：现象 → 原因 → 结论。目标是下次遇到同类问题时少走一遍。

## 1. 一个日志文件不是一个压缩流

- **现象**：`zstdDecompressSync` 对 3.3MB 的会话日志只返回 229 字节，命令行 `zstd -dc` 却能解出 11MB。
- **原因**：DSH 每次 flush 追加一个独立 zstd 帧，文件是多帧拼接；Node 的同步解压只解第一帧。
- **结论**：按帧结构（magic → 帧头 → 块头 → 末块标志）自己找边界，再逐帧解压。测试用"两帧拼接"的合成文件，不能只测单帧。

## 2. 改配置前先确认"哪个 profile 是活的"

- **现象**：把插件装进 `~/.dsh/profiles/web` 并重启，设置页毫无变化。
- **原因**：DSH Desktop 实际使用 `~/Library/Application Support/dsh-desktop/harness/profiles/web`；`~/.dsh` 是旧的 CLI 目录。两者结构相同，很容易看错。
- **结论**：先读 `$DSH_PROFILE_DIR` 或进程环境，再写配置。安装、备份、回滚都针对同一个目录。

## 3. 客户端 bundle 不需要构建工具

- **现象**：以为必须配 TypeScript + tsdown 才能写界面。
- **原因**：DSH 的要求只有三件事：`package.json` 导出 `./client`、声明 `dsh.client`、bundle 里调用 `window.__ModuleLoader__.load({ id, factory })`。
- **结论**：小界面可以直接手写 `React.createElement`，零构建、改完即生效。代价是不能写 JSX；界面继续变大再评估 esbuild。

## 4. 变量名正确，不代表颜色可见

- **现象**：热力图所有格子都是灰色。
- **原因**：深色主题下 `--dsw-alias-brand-primary` 是 `neutral-bluish-1000`（深藏蓝），铺在深色面板上几乎看不见。
- **结论**：主题变量要**验证取值**，不能只看名字。改用 `--dsw-static-blue-450` + 透明度分档，明暗主题都成立。

## 5. 本地日志 ≠ 平台账单

- **现象**：插件显示 279M，官方用量页 341M。
- **原因**：本地只统计仍然存在的会话日志；官方统计账号侧全部调用。已删除会话、标题生成、联网搜索、失败重试都不在日志里。
- **结论**：先对账、再决定口径，并把限制写进界面。宁可显示偏小，也不要估算出一个"看起来很精确"的假数字。

## 6. 客户端改动不需要重启 Harness

- **现象**：每次改界面都要重装插件、重启宿主，迭代很慢。
- **原因**：profile 使用 hoisted linker，`file:` 依赖被复制进 `node_modules`；宿主从那里提供客户端 bundle。
- **结论**：客户端改动只需把 `lib/client.js` 复制到 profile 的 `node_modules/dsh-usage/lib/`，刷新页面即可。宿主代码改动才需要重启。开发期可以改用 `link:` 依赖，省掉复制。

## 7. 精确数字会撑破按缩写设计的布局

- **现象**：5 张卡片一行放不下，累计数字被截成 `27`；热力图把整页撑宽，左边的卡片被裁掉。
- **原因**：参考设计里的 `3.3亿` 很短，而 `294,483,483` 长得多；固定 53 列的网格也会超过侧栏宽度。
- **结论**：先拿真实数据量一遍再定布局。最终改为两行卡片（3+2），热力图放进独立的横向滚动容器。

## 8. vm 里的数组不是"同一个数组"

- **现象**：在 `node:vm` 里执行 bundle，返回的数组用 `deepStrictEqual` 与本地数组比较会失败，但打印出来一模一样。
- **原因**：不同 realm 的 `Array.prototype` 不同，严格比较会看原型。
- **结论**：用 `Array.from(...)` 转成本地数组，或逐项比较。

## 9. 测试替身要能承载多个 Hook

- **现象**：组件加了第二个、第三个 `useState` 之后，旧的假 React 让所有状态共用一个变量，测试开始出现莫名其妙的串值。
- **原因**：假 `useState` 只有一个槽位。
- **结论**：测试替身按调用顺序分配槽位（`states[index++]`），并在每次渲染时重置索引。替身越像真实运行时，测试才越可信。
